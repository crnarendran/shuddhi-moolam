# User Guide

> **Status: stub.** This is a Docs-first placeholder. The `/docs` role fills
> each section as the corresponding backlog ticket (SM-01…SM-10) lands. Do not
> treat unfilled sections as final behavior.

## Who this is for

The person who receives the weekly newsletter and owns the master spreadsheet.
You don't run any code — you just drop PDFs into a Drive folder and read the
results in the sheet.

## Uploading a newsletter
_To be documented with ingestion (SM-02 / SM-03)._ Which Drive folder to use,
whether subfolders are watched, and what filenames are expected.

## Where the data lands
_To be documented with routing (SM-06 / SM-07)._ How year tabs (`Data_<year>`)
are named and created, the column order, and how a re-uploaded file is handled
(no duplicate rows).

## Reading a row
_To be documented with extraction (SM-05)._ What each column means (cross-links
to the Domain Model), and why prices may appear as ranges/text.

## When something looks wrong
_To be documented with observability (SM-08)._ How extraction failures surface,
and how to request a re-process.
