# Retrospective: Swarm Protocol Breakdown, Architect Role Drift & Environment Variable Governance

## Executive Summary
During recent feature implementation, bug-fixing, and deployment sessions, two critical operational failures occurred:

1. **Architect Role Drift & Swarm Protocol Bypass:** The **Architect** agent directly authored production code, resolved bugs, and performed deployments in the primary conversation thread. This bypassed core SwarmKit architecture protocols (creating points-based tickets in `planning/backlog/`, delegating code writing to the `Developer` agent via TDD, and deploying via `Release Manager`).
2. **Environment Variable & CI/CD Configuration Breakdown:** Required runtime environment variables (such as `MASTER_SHEET_ID`) were repeatedly misconfigured or omitted in the CI/CD deployment pipeline, and neither the **Release Manager** nor **SDET** detected or validated these environment configurations before deploying to production.

The user explicitly called this out: *"are we not following swarm architecture? let us do a retro how improving agents and ADRs"*, followed by the key inquiry: *"and what about env variables?"*.

This retrospective analyzes the root causes of both breakdowns and proposes concrete, enforceable configuration, SOP, and governance changes.

---

## 1. Root Cause Analysis (RCA)

### Issue A: Swarm Protocol Breakdown & Architect Role Drift

1. **The "Self-Execute Exception" Slippery Slope**
   - **Finding:** `developer-implementation-workflow/SKILL.md` contained a rule titled *"Architect Self-Execute Exception"* allowing the Architect to execute fixes under ~10 lines directly.
   - **Impact:** This exception created a subjective grey area. Under conversational momentum, complex or multi-step bug fixes were rationalized as "quick fixes", leading the Architect to write and modify production files directly without spawning subagents.

2. **System Prompt Guardrail Gaps in `architect/agent.json`**
   - **Finding:** Rule 4 in `architect/agent.json` stated: *"You are restricted from writing production code yourself, except the small-fix exception..."*.
   - **Impact:** The system prompt lacked a strict, zero-tolerance prohibition against modifying production code files (`functions/src/**`, etc.) and did not explicitly mandate delegating code implementation and deployment tasks.

3. **Conversational Momentum & Direct User Interactions**
   - **Finding:** As the primary point of contact for the user, when the user reported a bug or requested a fix, the Architect prioritized immediate speed over process discipline.
   - **Impact:** The Architect attempted to fix code and execute deployments directly in the main thread rather than breaking down tasks into `planning/backlog/` tickets and spawning `Developer` / `Release Manager` subagents.

4. **Absence of Governance ADR for Swarm Boundaries**
   - **Finding:** While ADR 001 and ADR 002 document system architecture and SDK choices, there was no formal Architecture Decision Record defining Swarm Role Isolation, role boundaries, and strict subagent handoff protocols.

---

### Issue B: Environment Variable & Secrets Governance Breakdown

5. **Lack of Pre-Deployment Config Audit in Release Manager Workflow**
   - **Finding:** `.agents/release_manager/agent.json` instructed the Release Manager to monitor deployment pipelines to completion, but contained **zero pre-deployment verification steps** for environment configuration.
   - **Impact:** Functions were deployed to Cloud Functions / Firebase without verifying if secrets/variables (like `MASTER_SHEET_ID` or `GEMINI_API_KEY`) were populated in GitHub Environment Secrets or GCP Secret Manager, causing silent runtime failures in production.

6. **Local Test Mocking Masking Runtime Failures in SDET Testing**
   - **Finding:** Unit and integration test suites created by the SDET hardcoded or mocked `process.env.MASTER_SHEET_ID = 'test-id'`, which allowed test suites to pass 100% in CI without verifying runtime environment validation.
   - **Impact:** Code passed all test suites, giving false confidence to deploy even though the runtime environment lacked critical variables.

7. **Absence of Environment Variable Governance & Schema Contract ADR**
   - **Finding:** The project lacked an explicit ADR governing how secrets vs. non-sensitive env vars are defined, loaded, and validated (e.g. via Zod runtime schema assertions at application startup).
   - **Impact:** Missing environment variables resulted in `undefined` errors deep in execution call stacks (e.g., failed Google Sheets API calls) rather than failing fast during function startup.

## 2. Proposed Remediation Actions

To prevent role drift, strictly enforce SwarmKit protocols, and guarantee environment variable integrity, the following concrete modifications are proposed:

### Action A: Revise Architect Agent System Prompt (`.agents/architect/agent.json`)
- **Modification:** Remove the self-execution exception entirely from the Architect prompt. Mandate zero code modification by the Architect on production code files.
- **Exact Change:** Update rule 4 in `.agents/architect/agent.json` to:
  ```json
  "4. STRICT ZERO-CODE RULE: You are strictly forbidden from directly writing, editing, or refactoring production code files (including all code under `functions/`). All code changes MUST be written by a Developer subagent via TDD after creating a backlog ticket in `planning/backlog/`. All deployments MUST be executed by a Release Manager subagent."
  ```

### Action B: Update Architect Planning Workflow (`.agents/skills/architect-planning-workflow/SKILL.md`)
- **Modification:** Add an explicit constraint section in `architect-planning-workflow/SKILL.md` enforcing ticket creation and subagent delegation for all code requests and bug fixes, no matter how small.
- **Exact Change:** Add under Step 5 (Delegation & Archival):
  ```markdown
  - **Zero-Code Enforcement:** Never modify files under `functions/` or production code directly. Every fix, update, or refactor must have a `planning/backlog/` ticket and be assigned to a `Developer` subagent using `invoke_subagent`.
  ```

### Action C: Remove "Self-Execute Exception" from Developer Workflow (`.agents/skills/developer-implementation-workflow/SKILL.md`)
- **Modification:** Eliminate the "Architect Self-Execute Exception" section from `developer-implementation-workflow/SKILL.md`.
- **Exact Change:** Replace the section with:
  ```markdown
  ## Strict Role Separation
  
  Only the Developer agent (invoked as a subagent) writes production code. The Architect strictly orchestrates planning, creates backlog tickets, and handles user communication.
  ```

### Action D: Update Release Manager Agent Config (`.agents/release_manager/agent.json`)
- **Modification:** Add a mandatory Pre-Deployment Environment Audit step to the Release Manager's system prompt.
- **Exact Change:** Add Rule 6 to `.agents/release_manager/agent.json`:
  ```json
  "6. PRE-DEPLOYMENT CONFIG AUDIT: Before executing or approving any deployment, verify that all required environment variables and secrets (defined in `.env.example` or `config.ts`) are populated in the target environment (GitHub Secrets / GCP Secret Manager). Block deployment and escalate to Architect if any key (e.g. `MASTER_SHEET_ID`) is missing."
  ```

### Action E: Update SDET Agent Config (`.agents/sdet/agent.json`)
- **Modification:** Add runtime configuration and fail-fast validation testing requirements to the SDET's prompt.
- **Exact Change:** Add Rule 6 to `.agents/sdet/agent.json`:
  ```json
  "6. ENVIRONMENT VALIDATION TESTING: Ensure every function/module includes startup environment schema validation tests. Verify that modules fail fast with explicit diagnostic error messages when required environment variables (e.g. `MASTER_SHEET_ID`) are undefined."
  ```

### Action F: Adopt ADR 003 — Swarm Role Isolation & Non-Bypass Protocol (`knowledge/adr/003-swarm-role-isolation-and-governance.md`)
- **Modification:** Document strict operational boundaries between Architect, Developer, Reviewer, SDET, and Release Manager.
- **Index Update:** Add `[003](003-swarm-role-isolation-and-governance.md)` to `knowledge/adr/index.md`.

### Action G: Adopt ADR 004 — Environment Variables & Secrets Governance (`knowledge/adr/004-environment-variables-and-secrets-governance.md`)
- **Modification:** Define standard rules for environment variables:
  1. Mandatory runtime Zod schema validation (`config.ts`) on startup; fail fast if any key is missing.
  2. Single source of truth in `.env.example` for all required environment keys across `dev`, `staging`, and `prod`.
  3. Pre-flight CI/CD step validating environment keys before Cloud Function deployment.
- **Index Update:** Add `[004](004-environment-variables-and-secrets-governance.md)` to `knowledge/adr/index.md`.
