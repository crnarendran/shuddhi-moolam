# Retrospective: Incident SM-18 — Gaxios Transitive Dependency Pinning & API Incompatibility Breakdown

## Executive Summary

During the resolution of **SM-18** (Fixing `URLSearchParams` crash in Drive download `gaxios` bug), an incident occurred that broke the Google Drive webhook handler across all environments (`dev`, `staging`, `prod`):

- **Incident:** To fix a `Value of "this" must be of type URLSearchParams` crash in `drive.files.get({ alt: 'media' })`, the team pinned `gaxios` to `6.5.0` via npm `overrides` in `functions/package.json`.
- **Review Breakdown:** The Reviewer approved the PR after checking that `package-lock.json` updated cleanly and unit tests passed, without auditing whether `googleapis-common@173` was API-compatible with `gaxios@6.5.0`.
- **Deployment & Outage:** The fix was deployed across all three environments. At runtime, `googleapis-common@173` called `Gaxios.mergeHeaders` — a static method present only in `gaxios@7.x`. Downgrading to `6.5.0` caused immediate `TypeError: Gaxios.mergeHeaders is not a function` crashes, completely breaking the webhook handler across all environments.
- **Root Cause & Correct Fix:** `gaxios` should have been upgraded to `7.3.0` (the latest release in the 7.x major version family), which preserved `Gaxios.mergeHeaders` while eliminating the `URLSearchParams` bug.

This retrospective documents the root causes of this review and verification failure, and proposes concrete changes to SwarmKit workflow files (`.agents/skills/developer-implementation-workflow/SKILL.md`) and agent system prompts (`.agents/reviewer/agent.json`, `.agents/developer/agent.json`, `.agents/release_manager/agent.json`).

---

## 1. Root Cause Analysis (RCA)

### RCA 1: Reviewer Lock-File Tunnel Vision & Lack of Transitive API Compatibility Audit
- **Finding:** `.agents/reviewer/agent.json` instructed the Reviewer to check code against backlog tickets and ADR specs, but lacked rules requiring verification of API compatibility for transitive dependency overrides.
- **Impact:** The Reviewer verified that `package-lock.json` generated cleanly, but failed to detect that `gaxios@6.5.0` removed `Gaxios.mergeHeaders`, a static method called by `googleapis-common@173`.

### RCA 2: Omission of Live API Diagnostic Scripts from Pre-Promotion Checklist
- **Finding:** The deployment workflow relied solely on mocked Jest unit tests (`npm test`). Neither `.agents/skills/developer-implementation-workflow/SKILL.md` nor `.agents/release_manager/agent.json` mandated running the live diagnostic script (`diag-webhook.cjs`) prior to branch promotion and deployment.
- **Impact:** The `Gaxios.mergeHeaders` crash was missed during local testing and CI, manifesting only after full multi-environment deployment.

### RCA 3: Major Version Downgrade of Transitive Dependency Across Family Boundaries
- **Finding:** Developer attempted to fix a bug in `gaxios@6.6+` by downgrading to `6.5.0`, ignoring that the primary consuming package (`googleapis-common@173`) was built for the `gaxios` 7.x major version family.
- **Impact:** Crossing major version boundaries downwards broke consumer API contracts. The correct resolution was upgrading to `gaxios@7.3.0` within the 7.x family.

## 2. Proposed Remediation Actions

To prevent transitive API incompatibility and ensure pre-promotion live verification, the following concrete modifications are proposed:

### Action A: Update Developer Implementation Workflow (`.agents/skills/developer-implementation-workflow/SKILL.md`)
- **Modification:** Add strict Transitive Dependency Override Rules and mandate live diagnostic script execution in the pre-promotion checklist.
- **Exact Changes:**
  1. Add a **Transitive Dependency Override Rules** section under Implementation:
     ```markdown
     ## Transitive Dependency Override Rules
     - **Major Version Family Alignment:** When overriding or pinning a transitive dependency version to fix a bug:
       1. Inspect the dependency requirements of primary consuming packages (e.g., `googleapis` / `googleapis-common`).
       2. NEVER downgrade a transitive dependency to a previous major version family (e.g. `gaxios` 6.x) if the primary package requires the current major version family (7.x).
       3. Always verify and upgrade to the latest release within the CURRENT major version family (e.g. `7.3.0` instead of `6.5.0`).
     ```
  2. Update **Step 3 (Validation & Diagnostic Check)**:
     ```markdown
     ## Step 3: Validation, Live Diagnostic & Escalation Check
     - **Live Diagnostic Verification:** Whenever dependency overrides or external API clients (e.g., Google Drive API) are modified, running unit tests with mocks is NOT sufficient. You MUST execute live diagnostic scripts (e.g., `diag-webhook.cjs`) against live APIs as part of the pre-promotion checklist before submitting for review.
     - Follow `.agents/skills/human-escalation-policy/SKILL.md`.
     ```

### Action B: Update Reviewer System Prompt (`.agents/reviewer/agent.json`)
- **Modification:** Add mandatory Transitive Dependency & API Compatibility Audit rule.
- **Exact Changes:**
  - Add Rule 4 to `.agents/reviewer/agent.json`:
    ```json
    "4. TRANSITIVE DEPENDENCY & API COMPATIBILITY AUDIT: When reviewing PRs or changes that pin or override transitive dependency versions (e.g., in `package.json` overrides or resolution fields), do NOT rely solely on clean `package-lock.json` updates or local unit test mocks. You MUST explicitly audit API compatibility between the pinned transitive dependency version and its consuming packages (e.g. verifying imported static/instance methods, signature changes, or breaking changes like `Gaxios.mergeHeaders` between major versions)."
    ```

### Action C: Update Developer System Prompt (`.agents/developer/agent.json`)
- **Modification:** Add rule requiring major version family verification and live diagnostic script execution.
- **Exact Changes:**
  - Add Rule 5 to `.agents/developer/agent.json`:
    ```json
    "5. TRANSITIVE DEPENDENCY OVERRIDES: When pinning or overriding transitive dependencies, verify that the target version belongs to the CURRENT major version family required by primary consuming packages (e.g. `gaxios` 7.x for `googleapis-common`). Never downgrade major versions without verifying API compatibility, and always run live diagnostic scripts (e.g., `diag-webhook.cjs`) prior to submitting for review."
    ```

### Action D: Update Release Manager System Prompt (`.agents/release_manager/agent.json`)
- **Modification:** Add Pre-Promotion Live Diagnostic Checklist rule.
- **Exact Changes:**
  - Add Rule 8 to `.agents/release_manager/agent.json`:
    ```json
    "8. PRE-PROMOTION DIAGNOSTIC CHECKLIST: Before promoting code or executing deployment to `staging` or `prod`, verify that live diagnostic scripts (e.g., `diag-webhook.cjs` for live Google Drive API calls) have been executed and passed. Never deploy dependency overrides or API client updates without verified live API diagnostic execution."
    ```
